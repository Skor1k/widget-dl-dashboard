## Section 0 — ПЕРВЫЙ ЗАПУСК / «настрой проект»

**ТРИГГЕР:** пользователь написал «настрой проект», «установи зависимости», «запусти проект», «первый запуск», или просто открыл проект.

### ⚠️ ВАЖНО: что НЕ делать

- ❌ **НЕ запускай скилл `project-setup`** — он для пустой папки с нуля, здесь файлы уже есть
- ❌ **НЕ редактируй `webpack.config.js`** — там уже есть критичные патчи (IgnorePlugin + alias), они обязательны
- ❌ **НЕ пропускай шаг с токенами** — даже если пользователь просит только `npm start`
- ❌ **НЕ объявляй успех** без явного подтверждения от пользователя

### Шаги (строго по порядку)

**Шаг 1.** Выполни `npm install` (всегда, даже если `node_modules` существует).

**Шаг 2.** Задай оба вопроса ОДНИМ сообщением — точно в таком формате:

> Для завершения настройки нужны два значения:
>
> **1. FIGMA_ACCESS_TOKEN** — личный токен Figma.
> Как получить: figma.com → кликни на аватарку → Settings → Security → Personal access tokens → Generate new token → скопируй.
>
> **2. FIGMA_FILE_KEY** — ключ твоего рабочего файла в Figma.
> Как найти: открой нужный файл в Figma → из URL `figma.com/design/ЭТОТ_КЛЮЧ/...` скопируй часть после `/design/`.
>
> Пришли оба значения, создам `.env`.

**Шаг 3.** После получения токенов — создай `.env` (за основу возьми `.env.example`, подставь токены пользователя в `FIGMA_ACCESS_TOKEN` и `FIGMA_FILE_KEY`, остальные ключи оставь как есть из `.env.example`).

**Шаг 4.** Выполни `npm start`. Спроси пользователя:

> Откройте `localhost:3000` в браузере. Страница открылась? Откройте DevTools (F12) → вкладка Console — есть ошибки?

**Шаг 5.** Если ошибки — смотри раздел «Известные проблемы» в конце файла. Если всё чисто — сообщи об успехе и предложи `npm run build:plugin` (опционально).

**После успешной настройки:** создай `Tickets/ProjectSetup.md` (см. Section 0.5).

## Section 0.5 — ВЕДЕНИЕ ЗАДАЧ

Для каждой нетривиальной задачи создавай тикет в папке `Tickets/`.

**Зачем:** задачи часто спанят несколько сессий — тикет даёт контекст при продолжении работы.

### Claude Code

Используй встроенные инструменты:
- `TaskCreate` — создать задачу (subject + description)
- `TaskUpdate` — обновить статус (pending → in_progress → completed)

Дополнительно создай файл `Tickets/ИмяЗадачи.md` для межсессионного контекста.

### Другие агенты (Cursor, Codex, ChatGPT)

Создай файл `Tickets/ИмяЗадачи.md` со структурой:

```markdown
# [Название задачи]

**Статус:** in_progress / completed / blocked
**Создан:** YYYY-MM-DD

## Цель
Что нужно сделать и почему.

## Шаги
- [ ] Шаг 1
- [x] Шаг 2 (выполнен)
- [ ] Шаг 3

## Контекст
Ключевые решения, ограничения, что уже пробовали.

## Результат
(заполнить после завершения)
```

### Когда создавать тикет

Папка `Tickets/` может не существовать — создай её сам перед первым тикетом.

- Установка / настройка проекта → `Tickets/ProjectSetup.md`
- Реализация новой страницы → `Tickets/PageName.md`
- Перенос в Figma → `Tickets/FigmaSync.md`
- Дебаг сложной проблемы → `Tickets/BugXxx.md`

### Обновляй тикет

- В начале сессии: прочитай существующие тикеты → подхвати контекст
- В конце сессии: обнови статус, добавь что сделано и что осталось

## Правила разработки

- **Только компоненты из `@direct-frontend/components`** — никаких нативных HTML-тегов (`<h2>`, `<p>`, `<span>`, `<div>` и т.д.) там, где есть аналог в библиотеке.
- Если нужный компонент не найден в библиотеке — **спросить у пользователя**, не писать хардкод.
- Отвечать пользователю **только на русском языке**.
- **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО**: при получении картинки/скриншота с UI — начинать любые действия до того, как задан уточняющий вопрос пользователю.

## Обработка картинок с UI (ОБЯЗАТЕЛЬНЫЙ ПРОТОКОЛ)

**ТРИГГЕР:** пользователь прислал картинку/скриншот с интерфейсом.

**ШАГ 1 — ТОЛЬКО ЭТО, НИЧЕГО БОЛЬШЕ.** Задай вопрос:

> Что делаем с картинкой?
> 1. Сканировать и собрать интерфейс — распознать элементы и согласовать
> 2. Сгенерировать JSON для Figma-плагина — распознать, согласовать, создать JSON
> 3. Проработать баг — распознать контекст и начать дебаггинг

**Не делай ничего до получения ответа.** Ни описания, ни поиска иконок, ни верстки.

### После ответа «1 — Сканировать»

1. Опиши структуру текстом (все элементы сверху вниз, заголовки/кнопки/поля/алерты)
2. Спроси: «Всё верно? Есть что уточнить?» — жди подтверждения
3. Реализуй верстку по правилам проекта (только `@direct-frontend/components`)

### После ответа «2 — JSON для Figma»

1. Опиши структуру текстом
2. Спроси: «Всё верно?» — жди подтверждения
3. Создай JSON-дескриптор:
   - Корень: `{ name, page, card, variants[] }` или `{ name, page, card, children[] }`
   - Элементы: `{ type: "component", component: "...", props: {...}, text: "..." }`
   - Строки: `{ type: "row", gap: 16, children: [...] }`
   - Только компоненты из `COMPONENT_MAP` (`figma-plugin/src/component-map.ts`)
   - Сохранить в `figma-plugin/src/pages/<имя>.json`

### После ответа «3 — Баг»

1. Опиши что именно видно как проблему (что ожидалось vs что на картинке)
2. Систематически дебажь: root cause → гипотеза → минимальный фикс

### Красные флаги — СТОП

- «Картинка понятная, начну сразу» → **СТОП**, сначала вопрос
- «Найду иконки пока» → **СТОП**, сначала вопрос
- «Сгенерирую JSON без согласования» → **СТОП**, сначала согласование

## Стек

- React 18 + TypeScript
- `@direct-frontend/components` — дизайн-система (все UI-компоненты)
- Figma-плагин: `figma-plugin/src/`

```bash
npm start                                    # dev-сервер
npm run build:plugin                         # собрать Figma-плагин
npm run generate:figma -- src/FormPage.tsx   # TSX → JSON
```
